【标签证据规则】

每个非分类标签必须对应正文中的具体评测对象、任务设置、测量指标或失败机制。先找证据再选标签；没有直接依据就省略，不把相关词、产品功能或供应商列表变成能力标签。

- 知识库检索、RAG 或文档数量本身不等于“记忆”；只有实际讨论 Agent 跨轮次/任务保存、更新、遗忘或调用记忆及其验证时，才使用“记忆”或 Memory/Long-horizon。长文也不等于长程任务。
- 单一数学或编程竞赛、多模型组合、模型具有通用能力的宣传，都不足以标 Generalist Agent；需要材料确实评测跨不同任务或环境的通用 Agent。多个模型或多轮生成不自动构成 Multi-Agent。
- 客服场景中的查询、办理业务、遵循政策、用户打断等任务支持 Customer Service Agent；材料同时测量交易工具调用时，可再标 Tool/API Agent。涉及代码编写执行的 Agent 任务可标 Code Agent，不能仅凭出现代码片段贴标签。
- 鲁棒性要有噪声、扰动或环境变化下的评测；安全要有攻击、越权、风险行为或安全约束的测量，普通 bug 修复不自动标安全。任务规划、异常恢复、结果验证同样需要实际流程或失败证据。
- 实体只有在作为主要评测对象、作者或核心比较对象时才标；作为托管平台、兼容供应商或长榜单中的一个名字出现，不自动成为标签或 subjects。优先保留场景和能力，不用实体占满标签名额。
